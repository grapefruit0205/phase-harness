# 제품 명세

> 공개용 정제본이다. 서비스 코드·사설 교재·실행 증거는 포함하지 않으며 구현 또는 배포 완료를 주장하지 않는다.

## 목표와 첫 배포 범위

초대된 학습자가 사설 원본의 Linux 교재를 한국어 웹에서 순서대로 학습하고, 단원 평가로 오개념을 찾아 복습한다. 원문의 7단계 체계를 7개 단원으로 연결하되 하루 학습을 강제하지 않는다. Linux 안의 네트워크·SSH·DB 설명은 원문 범위에서 다룬다. 별도 Network/Database 과정, 실시간 셸 실행, 임의 인터넷 검색, 음성 튜터, 자율 서버 운영은 첫 배포 범위에서 제외한다.

이 문서는 구현 설계다. 서비스 구현·실제 모델 품질·배포 성공을 증명하는 산출물이 아니다. P00–P06은 fixture/fake provider로 완료할 수 있으며 실제 AWS 계정·source token·도메인은 후속 배포 단계에서만 필요하다. fixture 화면에는 모의 데이터임을 표시한다.

## 학습 흐름

1. 대시보드: 단원 목표, 선수 개념, section 진행률, 예정 복습, 이어 학습.
2. 단원: 설명·도식·조건이 명시된 명령 예시 → 핵심 개념 확인 → 학습 완료. 명령은 text로만 제공하고 사용자가 격리 VM에서 실행한다. 완료 표시는 이해도를 인증하지 않는다.
3. 마지막 필수 section 완료 시 server가 단원 8문항 평가를 멱등하게 자동 준비한다. server는 접근 가능한 active source version의 검증된 bank에서 blueprint를 충족하는 서로 다른 문항을 구성한다. 부족하면 생성/검토 상태와 학습으로 돌아가기 동작을 보여준다.
4. 평가는 기본 4지선다 8문항이고 제한 시간은 없다. 선택 저장·재접속 복구를 제공하며 제출 전 정답·해설을 전달하지 않는다. 8개 모두 응답해야 제출할 수 있고 server도 검사한다.
5. 결과는 점수, 정답 이유, 각 오답 이유, 관련 concept와 해당 version의 학습 section, 취약 concept 복습을 제공한다. source 접근 권한이 철회되면 숫자 기록만 남기고 교재를 재노출하지 않는다.
6. 학습자는 결과의 문항 오류를 신고할 수 있다. 관리자는 검토 뒤 문항을 철회하고 영향받은 복습/Memory를 감사 가능하게 정정한다.
7. 복습은 틀린 concept을 다시 학습하고 다른 검증 문항을 우선한다. 새 문항이 없으면 그 사실을 표시하며 같은 문제 반복을 새 숙련 증거로 계산하지 않는다.
8. 관리자는 source/media 동기화 실패, 출제 보류 이유, 문항 교육 검토·게시·철회, 생성 비용, audit를 본다.

기본 진행 기준은 8문항 중 6개 이상이다. 필수 concept 누락은 별도 복습을 추천한다. 한 번의 점수로 전문 역량이나 concept 숙련을 인증하지 않는다. 선수 section은 안내하고 단원 평가 자격은 그 단원의 필수 section 완료로 판단한다. 관리자 test account의 우회는 audit와 함께 명시한다.

## 자동화와 교육 승인

생성 model은 원문 근거로 후보를 만들고 독립 model 검토와 결정적 검사를 수행한다. 첫 운영 release는 `human_review_required` 정책이며 사람 교육 검토 전에는 전달하지 않는다. 관리자 승인 뒤 bank 보충·평가 구성·채점·복습 추천은 자동이다.

bank 부족 시 한정된 작업으로 후보를 보충한다. 자동 검사를 통과해도 사람 검토를 기다리는 상태는 `review_pending`이며 ready가 아니다. 완료 시각을 보장하거나 무한 재생성하거나 낮은 품질 문항으로 대체하지 않는다. 자동 게시 도입은 quality 평가 결과, 책임자, 대상 단원/model/prompt version을 기록한 별도 운영 변경이다.

검토용 기준문항 fixture는 `needs_human_review`, `approved_for_delivery=false`를 유지하며 운영 승인 bank로 자동 승격하지 않는다. production gate에는 모든 제공 단원에서 blueprint를 충족하는 교육 승인 bank가 필요하다. 없으면 구현 완료와 별개로 출시를 보류한다.

## 수용 기준

- 7단원·16개 section의 source mapping과 근거가 부족한 concept의 출제 차단.
- section 학습 → 8문항 평가 → 저장/재접속 → 제출 → 결과 → 복습 E2E와 한국어·keyboard·반응형 UI 검증.
- 사용자 격리·source 권한·관리자 역할 부정 test 통과. 제출 전 API/HTML/browser bundle에서 답·해설·채점 metadata 누출 없음.
- 출처 없음, 범위 밖 concept, 복수 정답, 입력의 prompt 지시는 보류. model 합의만으로 quality pass를 판정하지 않음.
- 일시 동기화 실패 시 마지막 접근 가능한 검증 version 유지. 확인된 삭제/권한 철회 시 그 version도 제공 중단.
- 실제 source/model/auth/DB/queue 연결은 staging에서, 승인 bank·운영 URL·복구 검증은 production gate에서 증거로 확인.
